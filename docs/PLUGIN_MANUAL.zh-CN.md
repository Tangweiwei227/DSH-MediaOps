# DSH-MediaOps 插件说明书

> 适用版本：0.2.x
> 项目主页：[github.com/Tangweiwei227/DSH-MediaOps](https://github.com/Tangweiwei227/DSH-MediaOps)
> 官网：[dsh-mediaops.tevin2501689480.chatgpt.site](https://dsh-mediaops.tevin2501689480.chatgpt.site)

DSH-MediaOps 是一个原生 DeepSeek Harness（DSH）插件。它把趋势发现、爆款收藏、选题管理、内容创作、多模态生产、跨平台发布和发布后复盘组织成一个可追踪的本地工作流，并把高频入口放回对话框：用 `@` 引用业务资料，用 `/` 启动固定流程，用自然语言决定下一步。

本说明书面向插件使用者、账号运营者和维护人员。第一次使用建议依次阅读「五分钟开始」「核心概念」「多模态模型配置」和「发布安全协议」。

## 1. 能做什么

DSH-MediaOps 提供六层媒体运营能力：

| 能力层 | Skills | 典型任务 |
|---|---:|---|
| 通用 | 6 | 素材、模板、资料、批处理 |
| 发现 | 9 | 热点、竞品、内容缺口、UGC、算法变化 |
| 策划 | 16 | 定位、受众、选题、内容矩阵、排期、活动 |
| 创作 | 50 | 文案、图片、卡片、音频、视频、短剧、复合内容 |
| 发布 | 20 | 平台适配、质量检查、风险扫描、发布、互动 |
| 归因 | 11 | 数据记录、评论洞察、复盘、ROI、策略迭代 |
| 合计 | **112** | 从发现到归因的完整闭环 |

插件提供的核心产品能力包括：

- 在对话中跨平台拉取热点，并逐个平台保留结果或失败信息；
- 将热点或外部案例保存到爆款库，再整理成有来源关系的选题；
- 用 `@` 搜索并引用选题、爆款等本地记录；
- 基于选题生成并保存跨平台草稿；
- 为图像、视频、音乐和云端语音 Skill 统一配置模型与 API；
- 通过 Host 受控连接器向 7 个平台提交内容；
- 对发布载荷做不可变冻结、两次原生审批和结果对账；
- 在 MediaOps 工作台查看概览、资料库、草稿、发布记录和模型状态。

DSH-MediaOps 面向单机个人工作流。它不是多人 SaaS、云端数据库、平台风控绕过工具，也不会保证第三方平台审核通过。

## 2. 五分钟开始

### 2.1 环境要求

- 可运行的 DSH Desktop 或 `dsh` CLI；
- Node.js 22.19+ 或 24+；
- 可从 `PATH` 找到的 pnpm，建议使用仓库声明的 pnpm 11.7.x；
- 需要运行具体 Skill 时，再安装该 Skill 声明的 Python、FFmpeg、Playwright 或第三方工具。

检查基础环境：

```sh
node --version
pnpm --version
dsh --version
```

### 2.2 安装

从 GitHub 安装到 DSH Desktop profile：

```sh
dsh plugin --profile desktop add github:Tangweiwei227/DSH-MediaOps
```

安装完成后完全退出并重启 DSH Desktop。仅关闭窗口但保留后台进程，可能不会重新加载 Host 插件。

### 2.3 验证

重新进入任意对话后，依次检查：

1. 对话视图出现 `MediaOps` 工作台入口；
2. 输入框键入 `@`，可以看到 MediaOps 资料来源；
3. 输入框键入 `/`，可以看到 MediaOps 快捷工作流；
4. DSH 设置页出现 MediaOps 区域；
5. 发送「列出 MediaOps 当前能力和资料库概览」，Agent 能调用只读工具并返回结果。

如果入口缺失，先看[插件未加载](#141-插件未加载或看不到-mediaops-入口)。

### 2.4 第一个闭环

依次发送：

```text
拉取今天微博、抖音和小红书的热点，每个平台 10 条；按与我的账号定位匹配度排序，先不要入库。
```

```text
把刚才第 2 和第 5 条收进爆款库，补充钩子、受众、结构和可复用点。
```

```text
把第 2 条爆款整理成 3 个差异化选题，先展示，等我选择后再入库。
```

入库后，在输入框键入 `@` 选择该选题，然后发送：

```text
基于这个选题写一版小红书图文稿，做质量检查，保存为 ready 草稿，但不要发布。
```

“不要入库”“不要发布”是明确约束。工具没有返回写入成功前，Agent 不应声称已经完成入库或发布。

## 3. 核心概念

### 3.1 爆款

爆款是值得复用或研究的外部案例。记录可以包含平台、链接、作者、热度、摘要、拆解笔记和标签。外部来源可能过期、删除或改变，因此链接只是来源信息，不是永久快照。

### 3.2 选题

选题是可用于你自己的内容方向。它可以由爆款整理而来，也可以直接创建。选题保留标题、角度、摘要、正文素材、平台、标签、状态和来源引用。

### 3.3 草稿

草稿是面向一个或多个平台的待审内容。典型状态包括普通草稿与 `ready`。只有 `ready` 草稿可以进入受控发布准备；内容改版会增加 revision，旧 revision 的发布回执不会误改新稿状态。

### 3.4 发布记录

每个平台对应独立发布记录，保留账号身份、载荷摘要、审批状态、执行结果和可核验证据。需要特别区分：

- `submitted`：平台已接受提交，不代表已经公开；
- `draft_created`：已创建到平台草稿箱；
- `scheduled`：平台已接受定时计划；
- `published`：已有可核验链接或回执证明内容已公开；
- `publishing`：执行已启动但结果仍不确定，禁止直接重发；
- `failed`：只有明确证据表明未产生内容时才使用。

### 3.5 Workspace root 与 data root

- **Workspace root**：当前对话的业务工作区。生成的文章、图片、音视频等产物写到这里；真实发布只接受这个目录内的普通文件。
- **Data root**：插件持久化状态、模型密钥、浏览器登录态、平台凭证与冻结发布载荷的位置。它不应位于 Git 仓库中。

二者不能混用。尤其不要把模型 API Key、Cookie 或浏览器 profile 放进业务工作区。

## 4. 对话即工作台

### 4.1 使用 `@` 引用资料

键入 `@` 后，选择 MediaOps 来源并搜索记录。被选中的条目保存的是“资料类型 + 稳定 ID + 展示名称”，不是简单粘贴一段标题。

消息真正提交时，客户端才向 Host 读取记录，并序列化成：

- 有固定来源声明；
- 有字符数上限；
- 对 XML 特殊字符转义；
- 明确标注为不可信资料而不是系统指令；
- 必要时带截断标记。

因此，手工键入 `@某标题` 或从剪贴板粘贴类似文字，不会自动变成结构化引用。

推荐表达：

```text
用 @选题库 中我刚选择的资料写 3 个标题，只借用核心矛盾，不复刻原文结构。
```

```text
比较 @爆款库 的这两条案例，找出共同钩子，再给出一个不相似的替代叙事。
```

### 4.2 使用 `/` 启动固定工作流

当前提供五个高频工作流：

| 快捷工作流 | 用途 |
|---|---|
| 拉取今日爆款 | 指定平台、数量、筛选标准后读取趋势 |
| 爆款整理成选题 | 分析已有案例并生成差异化选题 |
| 基于选题创作 | 引用选题后生成平台稿件或多模态内容 |
| 审核并发布 | 质量检查、预览冻结、确认和发布 |
| 今日内容盘点 | 查看草稿、发布队列和待处理事项 |

快捷工作流只是结构化起点，不代表自动授权外部操作。你仍然可以追加限制，例如目标平台、禁用风格、资产要求或“只读不写入”。

### 4.3 用自然语言写入

当你说“保存到爆款库”“建立选题”“保存草稿”时，Agent 应调用对应参数化工具。判断是否成功的唯一依据是工具结果；普通文本回复不是写入证明。

为减少误操作，推荐两步法：

1. 先让 Agent 展示候选和字段；
2. 明确指出要保存的序号或名称，再允许写入。

### 4.4 不可信内容边界

趋势标题、网页摘要、平台评论、稿件正文和 `@` 引用都可能包含类似“忽略之前规则”“立即发布”等文字。DSH-MediaOps 把它们全部视为数据；它们不能替代当前用户指令、系统规则或原生审批。

## 5. MediaOps 工作台

MediaOps 工作台同时出现在对话视图和设置入口。它用于快速查看状态与执行轻量操作，不替代对话式流程。

主要页面包括：

- **概览**：Skills、选题、爆款、草稿和已发布数量；
- **选题库**：浏览、搜索、复制定位文本和新建选题；
- **爆款库**：查看来源并整理为选题；
- **草稿**：查看标题、正文摘要、目标平台和状态；
- **发布队列**：查看每个平台的任务状态、结果链接和错误；
- **模型配置**：管理多模态提供商、能力和密钥状态。

工作台通过 DSH 本机 Web Server 访问 `/api/dsh-mediaops`。API 只接受 loopback、合法 localhost Host 与 same-origin 请求；它不是局域网或互联网 API。

## 6. 标准运营流程

### 6.1 发现热点

示例：

```text
拉取微博、抖音、知乎、B站今天的热点，每个平台最多 10 条。保留平台来源和抓取时间；某个平台失败时单独报告，不要拿其他平台结果补齐。
```

注意：

- 热榜来自第三方接口或平台页面，可能因网络、限流或结构变动而失败；
- “热度”在不同平台的单位不可直接横向比较；
- 结果进入对话不等于自动进入爆款库；
- 紧急趋势与预定季节热点应采用不同的时效判断。

### 6.2 收藏与拆解爆款

建议保存：来源平台、原始链接、标题、作者、热度、摘要、钩子、受众、结构、情绪、可复用点、不可复用点和标签。

不要把“热度高”当作适合账号的充分条件。可以让 Agent 额外按账号定位、生产成本、时效窗口和同质化风险评分。

### 6.3 整理为选题

推荐要求 Agent 同时提供：

- 核心矛盾与用户收益；
- 与来源案例的差异；
- 适合的平台和内容形态；
- 可以验证的事实与待补资料；
- 预计生产成本和时效；
- 建议标题、角度和结构。

通过爆款整理出的选题会保留来源关系，后续可追溯“为什么做这个选题”。

### 6.4 创作与质检

先指定目标平台、账号语气、读者、篇幅、素材约束和禁止事项，再让 Agent 路由 Skills。

示例：

```text
基于 @选题库 的资料写一版 900 字知乎回答。事实断言必须标出需要核实的来源，不使用夸张收益承诺。完成后做质量检查和版权风险检查，只保存为 draft。
```

多模态任务应提前说明输出规格：尺寸、比例、时长、字幕、画面一致性、声音授权与文件格式。生成模型配置见下一章。

### 6.5 发布与回收

发布前至少确认：

- 草稿状态为 `ready`；
- 平台与账号准确；
- 正文和素材是最终版本；
- 素材位于当前对话 workspace 内；
- 账号登录态和平台依赖可用；
- 已阅读完整预览，而不是仅看标题或摘要；
- 对定时、可见性、标签等参数没有歧义。

执行后遇到超时或崩溃，不要立即重发。先调用恢复/对账流程，避免同一内容被重复发布。

## 7. 多模态模型配置

部分图像、视频、音乐和云端语音 Skill 需要第三方模型 API。DSH-MediaOps 提供统一配置面板和 Host 受控运行入口，避免让 Agent 在对话、命令行参数或稿件中接触密钥。当前严格只有这四个模型组，不包含受管 ASR/语音转写；每次只运行明确选中的默认 Provider，不自动故障转移。

更详细的提供商兼容矩阵与字段说明见 [MULTIMODAL_MODELS.md](MULTIMODAL_MODELS.md)。

### 7.1 配置入口

打开 DSH 设置 → `多模态模型`。先选择模型类别与预定义 Provider，再填写该 Provider 所需字段：

- 是否启用此 Provider；
- API 根地址（Provider 使用内置官方默认值时可选）；
- API Key、Access Key / Secret Key 等凭证；
- 模型 ID 与该 Provider 的可选参数；
- 只有自托管服务确实需要时，才显式允许私有网络地址。

保存后，列表只显示密钥是否存在，不返回完整密钥或可识别片段。

### 7.2 密钥操作

编辑配置时，密钥有三种明确动作：

- **保留（keep）**：其他字段变化，继续使用现有密钥；
- **替换（replace）**：用输入的新密钥覆盖；
- **清除（clear）**：删除该提供商的密钥，依赖它的任务将不可运行。

空输入不会被猜测为清除。这个设计避免浏览器因为没有拿到原密钥而意外覆盖它。

### 7.3 能力路由

每个模型类别可以保存多个提供商配置，并明确选择一个默认提供商。任务执行前，Host 按脚本所属类别读取该默认项；未选择、未启用或配置不完整时返回缺失项，不会使用未知的隐式密钥，也不会自动故障转移到另一个提供商。

建议为生产任务固定模型 ID，而不是只写供应商的浮动别名。模型升级可能改变画风、时长、成本和审核规则。

### 7.4 验证与真实调用

“检查配置”默认只做离线校验，例如必填字段、URL、安全协议、能力与模型映射，不产生计费请求。

真正调用模型：

- 由 Host 选择预定义 Skill 脚本；
- 只允许固定脚本和参数形状；
- 禁止 `--model` 覆盖，并对数量、尺寸/质量/分辨率、时长、轮询/超时、语速和输入文件大小设置 Host 上限；
- 不使用 shell 拼接；
- 只注入该脚本需要的白名单环境变量；
- 公网 HTTP 始终拒绝；只有显式开启私网权限，且目标全部解析到 loopback、RFC1918 或 IPv6 ULA 时，私网 HTTP 才可用；
- API/轮询禁止 redirect；每次请求只连接一次 DNS 解析得到的已验证 IP，HTTPS 仍校验原主机名；媒体下载最多 3 跳并逐跳重新固定公网 HTTPS 目标；
- Provider 私网许可只作用于配置的 API endpoint，不会传给供应商返回的媒体 URL；响应按类型限长；
- Provider 请求前用 Host 注入的 device/inode 复核 workspace 与 `outputs/`，再以 `O_NOFOLLOW`、逐级 `dir_fd` 打开并持有目标父目录；partial 的创建、校验、`fsync`、原子替换和删除均相对该描述符执行；
- 受管语音转码让 FFmpeg 写入预先打开、可 seek 的普通文件描述符，再使用同一原子提交路径；
- 对输出中的常见密钥、临时凭证与 URL userinfo/query/fragment 做脱敏；
- 审批显示 provider、实际模型、规格与输入 basename/大小/SHA-256，但不显示 prompt/key；批准与同一调用一次性绑定，执行前配置和输入发生变化都会拒绝，本地输入以只读 snapshot 交给脚本；声音登记还必须确认样本上传和声音授权；
- 通过 DSH 原生审批后才执行可能计费的请求。

### 7.5 本地存储

模型配置保存在 data root 的私有文件中。目录尽力设置为 `0700`，含密钥文件尽力设置为 `0600`。密钥不会进入 `state.json`、草稿、发布载荷或 npm 包。

本地文件不做字段级加密。请启用操作系统磁盘加密，并限制设备账户访问。备份时把含密钥配置当作敏感凭证处理。

### 7.6 提供商与网络安全

- 优先使用官方 HTTPS API；
- 不要在服务地址中写用户名、密码或 API Key；
- 公网端点必须使用 HTTPS，开启私网权限也不会放行公网 HTTP；自托管 localhost/RFC1918/ULA 服务必须显式开启该 Provider 的私网权限，且私网 HTTP 的所有解析结果都必须落在这些范围；云 metadata、链路本地与其他保留地址始终拒绝；
- 受控模型网络请求不继承 Host 的 HTTP(S) 代理环境，以保证 DNS 校验的地址就是实际连接地址；
- 异常和 SIGTERM 会清理本次临时文件。模型子进程遭 SIGKILL、但 Host 与已批准目录身份保持正常时，Host 的 `finally` 按 run ID 精确清理；如果 Host 本身崩溃，启动/后续清理与定时 janitor 只在可信 v2 pending 记录能证明 owner 已死亡、且 workspace/`outputs/` inode 仍匹配时恢复；
- 活跃或身份无法确认的 owner 不会被清理；v1、截断或畸形 pending 记录会保守保留并且不读取其中路径。系统不承诺自动删除无法安全归属的残留；
- 使用第三方模型前，确认内容许可、数据保留、训练用途和地区合规要求；
- 文生图、文生视频的成功响应不自动代表素材拥有商用授权。

## 8. Skills 能力目录与路由

### 8.1 来源与优先级

插件内置 Easel 的 112 个 Skill 和共享资源。它们通过 bundled provider 提供：

1. 用户级或项目级同名 Skill 优先；
2. DSH-MediaOps bundled Skill 作为后备；
3. 相对 `resourceBase` 的脚本和 references 解析到插件包内；
4. Skill 正文在选中时才读取，产物仍写当前业务 workspace，不写已安装 npm 包目录。

当前 DSH provider 协议仍会把全部可调用 Skill 的名称与描述加入模型上下文；本版本没有宣称实现完整的分层按需展开。该限制及后续架构方向记录在 Issue #5。

完整逐项说明见 [CAPABILITIES.md](CAPABILITIES.md)。

### 8.2 能力选择建议

不要要求 Agent 无差别读取全部 Skill。先描述任务阶段、目标平台和产物形态，例如：

```text
这是“策划”任务：基于两个爆款找差异化角度，不生成正文，不调用发布类能力。
```

```text
这是“创作 / 视频”任务：输出 9:16、30 秒、带中文字幕的视频；先给分镜与成本预估，经我确认后再调用计费模型。
```

```text
这是“归因”任务：只读取已有发布记录和数据，不写入平台。
```

### 8.3 Host-only 发布 Skills

带真实平台写入、批量派发、通知、短链或排期派发路径的 13 个 Skill 不向模型和用户直接开放。真实平台脚本只能由 Host 发布 adapter 以固定 argv 执行。

发布层中的质量检查、内容改编、人设检查、SEO、版权风险与评论策略等只读或生成型 Skill 仍可正常调用。

| 哔哩哔哩 | `bilibili` | `skill-bilibili-upload` | 即时 `submitted`；定时 `scheduled` |

### 9.1 常见外部依赖

- 小红书、抖音、快手、视频号、知乎：Playwright、Chromium 和有效浏览器登录态；
- 微信公众号：`requests`、`PyYAML`、外置账号 YAML、有效 `app_id/app_secret` 和 IP 白名单；
- Bilibili：`biliup` CLI 与有效 Cookie；
- 多媒体处理：Python 3、FFmpeg、Pillow 或单个 Skill 声明的库。

平台可能触发验证码、设备验证、风控或人工审核。插件不会自动绕过这些机制。

### 9.2 微信公众号

当前连接器只创建草稿箱条目，默认不自动群发。群发会影响真实受众并可能消耗平台配额，应在单独验证权限、预览和审批语义后启用，不要把“已创建草稿”误判为“已群发”。

### 9.3 Bilibili 定时

Bilibili 是当前受控 adapter 中支持定时参数的平台。时间必须包含时区，且至少晚于当前时间 4 小时。其他平台出现“定时”字样不代表 Host 连接器已经提供可靠排期。

## 10. 发布安全协议

真实发布按以下顺序进行，任何一步都不能省略：

```text
preview → confirmed → publishing → submitted ─┐
                              ├→ draft_created ├→ published
                              └→ scheduled ────┘
             └──────────────→ failed（仅有未产生内容的证据）
preview / confirmed → cancelled
```

### 10.1 Host 账号探针与 dry-run

`mediaops_prepare_publish` 从当前 DSH 会话读取权威绝对 workspace，并检查：

- 草稿是 `ready`，或属于跨平台部分完成后的 `partially_published`；
- `accountKey` 精确匹配目标账号；
- 账号探针返回非敏感、稳定的 SHA-256 身份指纹；
- adapter 的无 `--exec` dry-run 成功；
- 素材是 workspace 内的普通文件，不是符号链接、相对路径或远程 URL。

### 10.2 不可变冻结

Host 将正文和本地素材复制到 data root 私有 staging 目录，记录：

- 草稿 revision；
- 正文与素材 SHA-256；
- 账号身份指纹；
- 平台参数和预检证据；
- `payloadDigest`。

预览令牌有效期为 30 分钟。长正文需要分页读完，不可用前 5,000 字摘要代替完整预览。

### 10.3 确认授权

你看完预览并明确说“确认发布”后，Agent 才能用相同一次性令牌调用 `mediaops_confirm_publish`。Host 再次校验令牌、摘要和幂等键，DSH 显示可信摘要并发起第一次原生审批。

这一步仅把状态变为 `confirmed`，不触网、不发布。

### 10.4 真实执行

`mediaops_execute_publish(publicationId, payloadDigest)` 会：

1. 重新核对冻结文件；
2. 展示平台、账号身份、正文哈希、素材安全路径、大小、哈希和参数；
3. 发起第二次原生审批；
4. 签发有时限的执行租约；
5. 再次探测账号身份；
6. 使用固定 argv、`shell: false` 启动唯一 adapter。

模型不能读取完整执行快照、修改载荷、替换账号或自行运行发布脚本。

### 10.5 结果与对账

平台明确接受后，状态先进入 `submitted`、`draft_created` 或 `scheduled`。只有官方域名链接或平台回执等证据可以把记录推进到 `published`。

如果执行启动后超时、中断、崩溃或结果不确定：

1. 保持 `publishing`；
2. 禁止盲目重发；
3. 调用 `mediaops_recover_publish` 获取只读对账包；
4. 查到回执后，经原生审批调用 `mediaops_record_publish_result`；
5. 仅在明确没有产生内容时记录 `failed`。

同一平台只要有任意 `publishing` 计划，就阻止新的真实执行，直到人工对账写入终态。

## 11. 数据目录、备份与迁移

### 11.1 Workspace root 解析

一般 Skill 的 workspace root 取首个非空值：

1. `DSH_MEDIAOPS_WORKSPACE`
2. `EASEL_ROOT`（兼容上游）
3. 当前进程工作目录

真实发布不接受模型或环境变量另报 workspace，而是使用当前 DSH 会话的绝对 `session.header.cwd`。

### 11.2 Data root 解析

data root 取首个有效值：

1. 插件 `config.dataDir`
2. `DSH_MEDIAOPS_DATA_DIR`
3. `$DSH_HOME/mediaops`
4. `~/.dsh/mediaops`

常见内容：

| 路径 | 用途 | 敏感性 |
|---|---|---|
| `state.json` | 选题、爆款、草稿、发布记录 | 中 |
| 模型提供商配置文件 | 模型端点、模型 ID、API Key | 高 |
| `staging/<publication-id>/` | 冻结正文和素材 | 高 |
| `wechat-publisher.yaml` | 公众号账号配置 | 高 |
| `credentials/` | Token、Cookie 等 | 高 |
| `browser-profiles/` | 平台浏览器登录态 | 高 |

### 11.3 备份

建议在 DSH 完全退出后备份 data root，以免同时写入。备份介质应加密。不要把 data root 直接提交到 Git、同步到公开网盘或发到 Issue。

恢复时保持原有目录权限，并在首次运行后检查：

- 状态 schema 是否完成迁移；
- 模型密钥仍只显示为脱敏状态；
- 浏览器登录态是否过期；
- 旧的 `preview` / `confirmed` 是否已按安全规则取消；
- 未完成 `publishing` 记录是否需要人工对账。

### 11.4 状态写入与迁移

状态写入采用进程内串行、跨 Host 文件锁、临时文件原子替换和最佳努力 fsync。单个状态文件上限 16 MiB。旧 schema 会在启动时迁移；无法安全恢复的待处理发布会被取消并销毁旧授权。

## 12. 插件配置

插件行 ID 为 `mediaops`。基础字段：

| 字段 | 默认值 | 范围/作用 |
|---|---:|---|
| `dataDir` | 空字符串 | data root；空值按上一章顺序回退 |
| `trendCacheTtlMs` | `60000` | 热榜内存缓存，5 秒至 1 小时 |
| `trendTimeoutMs` | `10000` | 单个平台请求超时，1 至 60 秒 |
| `maxReferenceChars` | `12000` | 单条 `@` 引用最大字符数，1,000 至 50,000 |

DSH 的 id 定向 patch 会整体替换该行 `config`，而不是深度合并，所以覆盖时要写全需要保留的字段：

```yaml
- id: mediaops
  name: dsh-mediaops
  config:
    dataDir: /Users/you/Documents/dsh-mediaops-data
    trendCacheTtlMs: 120000
    trendTimeoutMs: 15000
    maxReferenceChars: 16000
```

配置覆盖机制与组件关系见 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 13. 权限、安全与合规

### 13.1 默认安全边界

- 本地 API 只接受 loopback、localhost Host 和 same-origin；
- 所有外部内容与模型输出均视为不可信数据；
- `@` 引用有转义、来源声明与长度限制，但不是提示注入的绝对防护；
- 发布素材限制在权威 workspace 内，拒绝符号链接和远程 URL；
- 确认、真实执行与人工对账依赖 DSH 原生审批；
- Host-only Skills 不允许模型直接调用；
- 日志会尽力脱敏，但正确的秘密管理不能由日志脱敏替代。

### 13.2 文件与容量限制

单次发布正文与附件合计最多 20 个文件；单文件上限 2 GiB，总量上限 4 GiB，并预留 256 MiB 磁盘空间。跨预览 staging 使用跨进程锁和 6 GiB 全局配额。

### 13.3 内容合规

你仍需自行确认：

- 素材版权、肖像权、音乐授权和商用范围；
- 平台社区规则、广告法和行业监管要求；
- 生成式内容标识要求；
- 用户隐私、个人信息与跨境数据要求；
- 模型服务的内容保留和训练政策。

自动化成功不等于合规通过。平台接收内容也不等于平台认可内容合法。

### 13.4 报告安全问题

按 [SECURITY.md](../SECURITY.md) 使用 GitHub 私密渠道报告安全问题。不要在公开 Issue 中粘贴 Cookie、API Key、浏览器 profile、未发布正文或完整本机路径。

## 14. 故障排查

### 14.1 插件未加载或看不到 MediaOps 入口

1. 确认安装命令使用的是当前 DSH profile；
2. 完全退出并重启 DSH Desktop；
3. 检查 Node 与 pnpm 版本；
4. 查看 DSH Host 日志中是否有 `dsh-mediaops` 加载错误；
5. 本地开发安装时，确认修改 `src/` 后已运行 `pnpm build`。

### 14.2 `@` 搜不到记录

- 确认记录已经通过工具成功写入；
- 清空搜索词后再试；
- 检查本地 `/api/dsh-mediaops/topics` 或 `/viral` 是否返回错误；
- 确认没有把手工输入的 `@标题` 当作已选择的结构化记录；
- 检查 data root 是否指向了另一个 profile 或目录。

### 14.3 热榜为空或部分平台失败

- 区分“平台返回空列表”和“数据源请求失败”；
- 检查网络、DNS、代理和请求超时；
- 稍后重试，避免快速循环触发限流；
- 记录平台、数据源和抓取时间；
- 不要用另一个平台的结果冒充失败平台结果。

### 14.4 模型配置检查通过，但生成失败

离线检查不发送计费请求，所以仍可能存在：余额不足、模型无权限、地区限制、请求格式变化、内容审核、并发限制或服务端故障。

排查顺序：

1. 确认任务需要的能力有默认提供商；
2. 确认密钥状态为已配置；
3. 检查模型 ID 和官方服务地址；
4. 查看脱敏后的 Host 错误；
5. 用供应商官方控制台确认权限和余额；
6. 不要把完整密钥复制到对话或 Issue。

### 14.5 发布 dry-run 失败

常见原因：

- 账号 key 或昵称不精确；
- 浏览器登录态失效；
- Playwright / Chromium / `biliup` / Python 依赖缺失；
- 素材不在当前 workspace；
- 素材是符号链接、远程 URL 或超过容量限制；
- 公众号配置、IP 白名单或主题文件不匹配；
- Bilibili 定时时间不足 4 小时或缺少时区。

dry-run 失败意味着尚未真实发布。修复问题后重新准备即可。

### 14.6 发布卡在 `publishing`

不要重发。`publishing` 表示执行已经开始但结果未知，重复执行可能产生重复内容。

调用 `mediaops_recover_publish` 取得只读对账包，去平台后台确认是否产生草稿、审核中内容或公开内容，再经原生审批记录结果。无法确认时保持原状态并人工处理。

### 14.7 平台显示已提交，但插件不是 `published`

这是预期行为。`submitted`、`draft_created` 与 `scheduled` 都不是公开成功。取得官方链接或明确平台回执后再对账为 `published`。

## 15. 升级、卸载与开发

### 15.1 升级前

1. 等待正在执行的发布完成或完成对账；
2. 完全退出 DSH；
3. 加密备份 data root；
4. 阅读仓库 Release Notes 与迁移说明；
5. 不要删除 `publishing` 记录来绕过执行锁。

### 15.2 卸载

```sh
dsh plugin --profile desktop remove dsh-mediaops
```

卸载插件不会自动删除 data root、平台凭证、模型密钥或浏览器登录态。若确定不再使用，请先备份需要保留的数据，再使用系统文件管理器安全删除精确目录。

### 15.3 本地开发

```sh
git clone https://github.com/Tangweiwei227/DSH-MediaOps.git
cd DSH-MediaOps
pnpm install
pnpm check
```

安装当前工作树：

```sh
dsh plugin --profile desktop add file:/absolute/path/to/DSH-MediaOps
```

生产安装使用 `lib/index.js` 和 `lib/client.js`；修改 `src/` 后必须重新构建。提交前至少运行：

```sh
pnpm check
```

该命令应包含类型检查、测试、构建、frontmatter 检查和 npm 包清单检查。

## 16. 当前限制与路线图

- 热榜依赖外部数据源，平台变化可能导致单个平台暂时不可用；
- 发布后指标回收需要每个平台稳定的只读接口和身份验证，不能用页面抓取假装成可靠归因；
- 微信公众号默认只创建草稿，不自动群发；
- 目前只有 Bilibili 连接器支持受控定时参数；
- 多平台发布的每个平台应保留独立审批和状态，不能用“一次成功”覆盖部分失败；
- DSH 当前 Skill provider 协议会把可调用 Skill 的名称和描述展示给模型，完整的层级按需展开还需要 DSH 核心协议支持；
- `tts-voiceover` 和 `multi-voice-dubbing` 在 managed 模式下要求每段/每行云端生成单独审批，原批量脚本不可用；`short-drama` 的远程批量 generate/align 尚未改造为逐次受控调用，v0.2 只支持其不联网策划阶段；
- 本地状态没有字段级加密、多人权限、云同步或云端备份；
- 项目通过 GitHub 分发，不代表已经上架 DSH 插件市场。

公开规划和实现进度见 [GitHub Issues](https://github.com/Tangweiwei227/DSH-MediaOps/issues)。Issue 中的验收条件会先按当前 DSH 和平台能力复核；不可安全实现的部分会拆分，不以降低审批或证据标准换取“功能完成”。
