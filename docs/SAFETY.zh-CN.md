# 安全与隐私

发布前看清账号与内容；遇到结果不确定，先核对，再继续。

## 发布前，核对这四件事

1. **发给谁**：平台、账号昵称和受众是否正确。
2. **发什么**：完整正文、封面、图片和视频是否为最终版本。
3. **怎么发**：即时或定时、可见性、标签等参数是否符合预期。
4. **是否有权使用**：事实、图片、音乐、肖像和声音是否已核实或取得授权。

聊天中的“帮我发布”会启动准备流程。真实提交前，插件先核对账号、检查本地素材并生成冻结预览；你读完并明确确认后，还需要依次通过 DSH 的确认授权与真实执行审批。改稿或更换素材后，旧预览不能继续使用。

网页或导入资料中的“立即发布”等文字不是你的授权。最终以你核对的内容和 DSH 原生审批为准。

## 看懂发布结果

| 状态 | 对你意味着什么 | 下一步 |
|---|---|---|
| `preview` | 已准备预览，还没授权 | 阅读完整内容和账号 |
| `confirmed` | 已确认授权，还没执行 | 核对后决定是否批准真实执行 |
| `publishing` | 执行已开始，结果暂时不确定 | 先核对平台，不要重发 |
| `submitted` | 平台已接收，可能仍在审核 | 到后台核对公开状态 |
| `draft_created` | 已放入平台草稿箱 | 公众号当前到此为止，不会自动群发 |
| `scheduled` | 平台已接收定时计划 | 核对时间与后续发布结果 |
| `published` | 已有可核验的公开结果或平台证据 | 查看链接或回执，记录实际表现 |
| `failed` | 已有明确证据表明未产生内容 | 修复原因后重新准备 |

超时、断网或程序中断，都不等于发布失败。让 Agent 进行只读对账，再去平台后台核对；人工回填结果也需要 DSH 审批。当前并非所有平台都有自动回查和指标采集能力。

## 资料和账号保存在哪里

选题、爆款、草稿和发布记录默认保存在本机 `~/.dsh/mediaops`，也可能由你自定义到其他 data root。平台登录态、公众号配置和模型凭证也存放在该数据目录。生成的文章、图片和音视频保存在当前工作区，受管模型输出位于 `outputs/`。

模型设置按 data root 共享，同一数据目录下切换会话或项目不必重复配置。更换机器或数据目录不等于自动迁移。插件不提供多人权限、自动云备份或跨设备同步。

本地保存不等于加密：请保护电脑登录账户，启用系统磁盘加密，给备份介质加密。卸载插件会保留资料和凭证，避免误删；若不再使用，备份后再删除准确的数据目录。

## 哪些内容会发到外部

- 查看本地资料库不等于将资料公开。
- 拉取热点需要访问第三方数据源。
- 调用远程图像、视频、音乐或语音模型时，会向你选择的提供商发送生成所需内容；图生图或声音登记还可能上传输入素材。先确认服务的数据政策及素材授权。
- 真实发布会向目标平台提交预览中确认的内容和素材。

模型 API Key 在 DSH 设置中填写，不要发到聊天里，也不要放进文章、截图、代码仓库或问题反馈。界面只显示是否已配置，不会读回完整 Key。服务可能单独收费，“离线验证”不联网、不扣费，也不保证账号余额和模型权限有效。

## 保护你的账号与素材

平台可能要求扫码、验证码、设备验证或人工审核，请在平台正规流程中完成。MediaOps 不会绕过这些机制，也不保证审核通过、流量增长或内容商用授权。

生成素材仍需核对事实、版权和平台标识要求。声音克隆只应使用本人或已取得授权的声音。素材可用性以具体服务和权利人的授权为准；插件的开源许可证不会自动赋予生成素材商用权。

## 不小心暴露了密钥

先到对应模型或平台控制台撤销或轮换凭证；Cookie 泄露时按平台能力退出会话或重新登录。随后更新本机配置，并从公开内容和日志中移除秘密。只删除一条聊天或 Git 提交不会让泄露的密钥失效。

## 反馈问题

普通使用问题可通过[GitHub Issues](https://github.com/Tangweiwei227/DSH-MediaOps/issues)提交，说明版本、操作步骤和脱敏后的错误。不要附带完整 Key、Cookie、未发布正文、私有链接或浏览器登录资料。

发现凭证泄露、审批绕过等安全漏洞，请使用[私密漏洞报告](https://github.com/Tangweiwei227/DSH-MediaOps/security/advisories/new)，不要公开细节。项目维护默认分支的最新版本，预计七天内确认收到报告；DSH、浏览器、平台或模型服务本身的问题，也应联系其维护方。

需要了解实现边界时，可继续阅读[完整安全政策](../SECURITY.md)、[插件说明书](PLUGIN_MANUAL.zh-CN.md)和[技术架构](ARCHITECTURE.md)。
